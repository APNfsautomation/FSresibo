## Behavior worth knowing

* Both expense fields are **optional on save** and **required before a new export**. A blank is stored as `NULL`; nothing is defaulted, backfilled or deleted.
* Export is blocked **before** any review, workbook, Consumed or Archived change when a receipt **in the exact export set** lacks a field. Unselected and Archived receipts are never inspected.
* `Expense Account` accepts exactly `Day to day` and `Project Expense` (D / P then Tab). `Classification of Expense` accepts only the 39 approved values (source spelling `Accomodation` preserved). Text that is not an option is not kept. (Issue #56: the list grew to 41 with `Service Charge` and `Government Benefits`, appended; no migration. Missing expense fields no longer stop Review & Arrange from opening: they are completed in that dialog and saved by `Save Details & Export` with a targeted, update-time-guarded write.)
* The classification list lives in the app, not in a database CHECK, so the approved list can grow without a production migration. `expense_account` has a CHECK for its two fixed values.
* The quick-correction dialog carries the expense fields through; without that, saving a correction would have blanked them.
* TIN formatting runs only on typing, paste and autofill. Loading a historical value never rewrites it. Matching stays digits-only, so formatting cannot change a match.
* Monthly Filing: the confirmation dialog is unchanged; after the save, a Review & Arrange step orders the saved receipts for the workbook. Cancel exports and archives nothing (the saves stay). The Monthly cards keep their own order.

## Migration (UAT first)

`supabase/migrations/005_add_expense_fields.sql` is additive and nullable (`add column if not exists`, idempotent), leaves RLS, grants, triggers and `archive_monthly_filing_receipts()` untouched, and ships a UAT-only rollback comment.
**Apply order for any environment: migration first, then the frontend.** The v3.7.0 frontend writes `expense_account` and `classification_of_expense` on every save and fails against a database without them.

It points `config/supabase.js` at project `wnudewolpouussjtblis`, refuses secret/service-role keys and keys of any other project, marks the version `-uat+<sha>`, writes `BUILD-INFO.json`
